## O que mudou

### API e banco

- `AUTH_PROVIDER=legacy|supabase` e `SUPABASE_URL` na configuração. Padrão legacy
  mantém os ambientes existentes funcionando até ativação coordenada.
- Validação JWT via JWKS do projeto: ES256/RS256, assinatura, issuer, audience
  authenticated, exp/iat, subject UUID, session_id, role authenticated e proibição
  de identidade anônima. Falha de rede JWKS resulta em 503, não login permissivo.
- `POST /api/v1/auth/bootstrap` verifica identidade e provisiona workspace/usuário
  atomicamente, com subject único e tratamento de concorrência/idempotência.
- `GET /api/v1/auth/me` e APIs protegidas usam identidade externa no modo Supabase.
- Login/cadastro/refresh legados retornam 403 nesse modo. Não se emite um segundo
  JWT Nexus. Contas inativas continuam impedidas de entrar.
- Migração Alembic `0552c7d5fe36`, anterior `d82b966f6b46`: coluna UUID nullable
  `users.supabase_subject` com índice único. Preserva contas e dados existentes.
- Usuários externos usam sentinela de senha inutilizável `supabase:external`.
- Permissões vêm do banco local. `user_metadata` só fornece nome de exibição;
  campos como company_id e role enviados pelo usuário não concedem acesso.

### Frontend

- SDK `@supabase/supabase-js` fixado em 2.119.0.
- Google/GitHub com PKCE; e-mail/senha, criação com confirmação por e-mail,
  recuperação e atualização de senha; mensagens de erro e bootstrap com retry.
- Sessão bearer em sessionStorage por aba. Chave de canal SDK aleatória por
  instância evita que BroadcastChannel de outra aba troque o workspace atual.
- Apenas provas PKCE temporárias ficam em localStorage (validade de uma hora),
  separadas por `flow` UUID. Isso permite abrir e-mail de confirmação/recuperação
  em outra aba do MESMO navegador/origem. Tokens de acesso/refresh não são gravados
  nesse armazenamento compartilhado. Provas vencidas são descartadas na leitura.
- Preserva os namespaces de slots/índice/legado PKCE do SDK; callback captura
  `sb_flow_id` antes de limpar URL e passa-o explicitamente ao exchange.
- `/auth/callback` remove code/erros/flow/intent da URL; hashes de navegação
  existentes são preservados. Implicit access_token no fragmento é rejeitado.
- Recuperação persiste na aba até atualizar senha/sair. Falha de exchange ou
  ausência de sessão limpa esse estado para não prender a pessoa no formulário.
- Respostas tardias de bootstrap/refresh são descartadas após logout.
- Sessão por aba implica autenticar novamente após fechar a aba. Link de e-mail
  aberto em outro dispositivo não possui a prova PKCE: solicitar novo fluxo nesse
  dispositivo. Não confundir esse limite com suporte a nova aba, que foi testado.

## Como retomar localmente

- Python venv em `backend/.venv`; instalar `backend/requirements.txt` se necessário.
- Backend: `python -m alembic upgrade head`; `python -m pytest -q` com DATABASE_URL
  descartável. PostgreSQL cobre concorrência que SQLite não representa.
- Frontend: `npm ci`, `npm test -- --run`, `npm run build`.
- E2E: `NEXUS_TEST_DATABASE_URL` aponta para PostgreSQL descartável cujo nome
  começa com `nexus_e2e`; definir senha de seed exclusiva via `NEXUS_DEMO_PASSWORD`
  e `NEXUS_PYTHON` quando preciso; executar `npm run test:e2e` em frontend.
- `.env.local` é local/ignorado; nunca versionar tokens, DATABASE_URL real,
  senha de seed, service_role ou secret key. Somente publishable key no frontend.
